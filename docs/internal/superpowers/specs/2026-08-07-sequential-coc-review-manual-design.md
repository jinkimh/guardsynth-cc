# 연속 CoC 계약 구조 검토 한국어 매뉴얼 설계

**작성일:** 2026-08-07  
**상태:** 사용자 방향 승인, 문서 검토 대기  
**대상:** `artifacts/results/restricted/sequential-coc-consistency-v1/review/`

## 1. 목적

검토자 A와 B가 연속 CoC 텍스트에서 계약 구조만 일관되게 판정할 수 있도록
쉬운 한국어 매뉴얼과 합성 예제를 제공한다. 이 검토는 실제 차량 행동, 실제 객체
상태, 안전성 또는 CoC의 현실적 정답성을 판정하지 않는다.

## 2. 제공 위치

- `REVIEW_PROTOCOL.md`에는 처음부터 끝까지 읽을 수 있는 전체 한국어 매뉴얼을 둔다.
- `REVIEW_A.html`과 `REVIEW_B.html` 상단에는 검토 중 바로 확인할 수 있는 요약
  판단 순서, 선택지 뜻과 대표 합성 예제를 둔다.
- HTML의 27개 검토 항목, 불투명 `review_id`, A/B 고정 순서와 CSV 열은 바꾸지
  않는다.

## 3. 전체 매뉴얼 구성

### 3.1 검토자가 보는 증거

검토 화면은 CoC 문장과 첫 사건 기준 상대 시간만 제공한다. 영상, 그림, 궤적,
객체 상태, 검사기ㆍUPPAAL 결과, 후보ㆍ대조군 표시, 실제 장면ㆍ창 ID는 제공하지
않는다.

### 3.2 먼저 지킬 원칙

1. 문장에 적힌 내용만 판정한다.
2. 실제로 정지했는지, 장애물이 사라졌는지, 진행이 안전했는지는 추측하지 않는다.
3. 문장 자체가 모호하면 `AMBIGUOUS`를 선택한다.
4. 문장 구조는 명확하지만 실제 상태 증거가 있어야 관계를 결정할 수 있으면
   `EVIDENCE_REQUIRED`를 선택한다.
5. `CONTRADICTS`는 텍스트만으로 두 요구가 함께 성립할 수 없을 때만 선택한다.

### 3.3 항목별 쉬운 뜻

- `obligation_explicit`: 해야 하거나 하지 말아야 할 행동 의무가 문장에 명시됐는가.
- `required_action`: 명시된 행동을 정지ㆍ유지, 양보ㆍ감속, 가속ㆍ진행, 속도 유지,
  기타 또는 모호함으로 분류한다.
- `persistence_explicit`: 의무가 언제까지 계속되는지 문장에 명시됐는가.
- `release_condition_explicit`: 어떤 조건에서 의무가 끝나는지 명시됐는가.
- `ordered_steps_explicit`: 먼저ㆍ이후ㆍ그다음과 같은 행동 순서가 명시됐는가.
- `textual_relation`: 뒤 문장이 앞 계약을 지지, 명시적으로 충돌, 독립적으로 다룸,
  문장 자체가 모호함, 또는 외부 상태 증거가 필요함 중 무엇인가.
- `state_evidence_needed`: 실제 충족ㆍ해제ㆍ진행 가능 여부를 알려면 추가 증거가
  필요한가.
- `evidence_sufficiency`: 위 계약 구조 라벨을 텍스트만으로 판정하기 충분한가.
- `confidence`: 자신의 텍스트 판정 확신 정도다. 실제 상황의 확실성이 아니다.

### 3.4 `textual_relation` 판단 순서

1. 두 문장이 같은 의무를 유지하거나 명시된 다음 단계를 잇는가? 그러면
   `SUPPORTS`.
2. 텍스트가 해제 조건이 아직 거짓이라고 밝히면서 충돌 행동을 요구하는 등,
   문장만으로 양립 불가능한가? 그러면 `CONTRADICTS`.
3. 서로 다른 요구를 다루며 직접 관계가 없는가? 그러면 `INDEPENDENT`.
4. 표현 자체가 불명확한가? 그러면 `AMBIGUOUS`.
5. 관계를 정하려면 보행자ㆍ신호ㆍ장애물 같은 실제 상태를 알아야 하는가? 그러면
   `EVIDENCE_REQUIRED`.

## 4. 합성 예제

예제는 실제 제한 CoC, 실제 장면 또는 자동 검사기 결과를 사용하지 않는다.

### `SUPPORTS`

- 앞: “보행자가 지나갈 때까지 정지 상태를 유지한다.”
- 뒤: “보행자가 횡단 중이므로 계속 정지한다.”
- 이유: 뒤 문장이 같은 정지 의무와 지속 조건을 지지한다.

### `CONTRADICTS`

- 앞: “신호가 녹색이 될 때까지 정지한다.”
- 뒤: “신호가 아직 적색이므로 출발한다.”
- 이유: 뒤 문장이 해제 조건이 성립하지 않았다고 명시하면서 출발을 요구한다.

### `EVIDENCE_REQUIRED`

- 앞: “보행자가 지나갈 때까지 정지한다.”
- 뒤: “이제 출발한다.”
- 이유: 보행자가 실제로 지나갔는지 텍스트에 없으므로 지지 또는 충돌을 확정할 수
  없다.

### `INDEPENDENT`

- 앞: “앞 차량과 거리를 유지한다.”
- 뒤: “다음 교차로의 우회전 경로를 확인한다.”
- 이유: 두 요구 사이의 유지ㆍ해제ㆍ순서 관계가 명시되지 않았다.

### `AMBIGUOUS`

- 앞: “상황에 따라 속도를 조절한다.”
- 뒤: “적절한 시점에 진행한다.”
- 이유: 요구 행동과 조건이 구체적이지 않아 텍스트 관계 자체를 정하기 어렵다.

### 순서가 명시된 정상 관계

- 앞: “교차로 진입 전에 먼저 정지한다.”
- 뒤: “주변을 확인한 다음 교차로를 통과한다.”
- 이유: 정지→확인→진행 순서가 명시되어 `ordered_steps_explicit=YES`이고 관계는
  `SUPPORTS`다.

## 5. HTML 요약 안내

HTML 상단 안내는 전체 문서를 그대로 반복하지 않고 다음만 제공한다.

- “실제 상태나 안전을 판단하지 않는다”는 경고
- `AMBIGUOUS`와 `EVIDENCE_REQUIRED`의 차이
- 다섯 `textual_relation` 선택지의 한 줄 뜻
- `CONTRADICTS`와 `EVIDENCE_REQUIRED`를 비교하는 두 대표 합성 예제
- 각 항목을 판정하는 5단계 순서

긴 안내가 27개 항목을 가리지 않도록 접어서 펼칠 수 있는 한국어 도움말 영역으로
제공하되 JavaScript 없이도 내용을 읽을 수 있어야 한다.

## 6. 블라인딩과 보안

- 합성 예제만 사용하며 제한 CoC 원문을 매뉴얼ㆍ시험 fixtureㆍSDD 보고서에
  복사하지 않는다.
- 검사기 결과, 후보ㆍ대조군, 원본ㆍ변형, 실제 scene/window ID를 노출하지 않는다.
- CoC 원문은 기존처럼 escaped HTML에만 두고 JavaScript 데이터에는 넣지 않는다.
- 기존 사람 CSV가 하나라도 있으면 패킷을 다시 만들지 않고
  `REVIEW_ALREADY_STARTED`로 중단한다.
- review 디렉터리는 `0700`, 문서와 HTML은 `0600`을 유지한다.

## 7. 검증

- TDD로 전체 매뉴얼의 필수 판단 규칙과 HTML 요약 예제가 생성되는지 검사한다.
- 실제 만족ㆍ해제 질문, 안전ㆍ정답 판단, 금지 metadata가 계속 부재하는지 검사한다.
- A/B membership은 동일하고 순서만 다르며 27개 독립 cluster를 유지한다.
- 패킷을 원자 재생성한 뒤 packet manifest, 누적 `MANIFEST.sha256`과 `RUN_LOG.md`를
  갱신한다.
- focused review tests, 전체 licensed test suite, actual verifyta 포함 `all`,
  `sha256sum -c MANIFEST.sha256`을 실행한다.
- 사람 CSV가 없으므로 최종 상태는 계속 `WAITING_FOR_CONTRACT_REVIEW`이고 KIEE 원고는
  수정하지 않는다.

## 8. 성공 기준

- 처음 검토하는 사람이 각 필드와 다섯 텍스트 관계 선택지의 차이를 한국어로
  이해할 수 있다.
- 특히 `CONTRADICTS`와 `EVIDENCE_REQUIRED`를 실제 상태 추측 없이 구분할 수 있다.
- 합성 예제만 사용하고 블라인딩ㆍ표본ㆍCSV 계약ㆍ권한ㆍ해시가 유지된다.
- 새 매뉴얼 배포가 기존 사람 답변을 덮어쓰지 않는다.
