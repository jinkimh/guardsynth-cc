# KIEE 복사본 한국어 문장 개선 설계

## 1. 목적

KIEE 심사용 독립 복사본의 한국어 표현을 학술적으로 정확하면서도 한 번에
이해할 수 있는 문장으로 고친다. 영어를 직역한 명사 나열, 뜻이 불분명한
전문 용어, 주어와 서술어가 맞지 않는 긴 문장을 우선적으로 개선한다.

## 2. 수정 대상과 보존 대상

수정 대상은 다음 디렉터리의 KIEE 복사본으로 한정한다.

`papers/demestic-journal/latex-kiee-review-2022-coc-audit`

수정 대상은 한국어 제목, 10개 절의 한국어 본문, 표 안의 한국어 문구,
그림ㆍ표의 한국어 캡션이다. 영문 제목, 영문 초록, 영문 핵심어, 영문 캡션,
참고문헌은 수정하지 않는다.

원본 `papers/demestic-journal`과 KIEE 참조 양식은 수정하지 않는다.

## 3. 문장 편집 원칙

1. 한 문장에는 핵심 주장 하나를 담는다.
2. 긴 명사 나열은 원인, 검사 방법, 결과, 의미를 나타내는 문장으로 나눈다.
3. 주어를 생략했을 때 의미가 모호하면 주어를 명시한다.
4. 주어와 서술어, 조사와 호응 관계를 바로잡는다.
5. 처음 등장하는 개념은 쉬운 문장으로 설명한 뒤 짧은 용어를 사용한다.
6. 영어 직역 표현보다 국내 소프트웨어공학ㆍ자율주행 논문에서 자연스럽게
   이해할 수 있는 한국어를 우선한다.
7. 지나치게 긴 괄호와 슬래시 나열을 줄이고 필요한 경우 문장으로 풀어 쓴다.
8. 동일한 개념에는 논문 전체에서 동일한 한국어 용어를 사용한다.

## 4. 핵심 용어 처리

용어는 기계적으로 일괄 치환하지 않고 문맥에 따라 다음과 같이 쓴다.

| 기존 표현 | 권장 표현 | 적용 기준 |
|---|---|---|
| 감사 | 검증, 점검, 검토 | 계약 충족 여부는 `검증`, 데이터 상태 확인은 `점검`, 사람이 다시 볼 대상은 `검토` |
| 감사 계약 | 검증 계약 또는 시간ㆍ출처 검증 조건 | 처음에는 의미를 풀어 쓰고 이후 짧은 표현 사용 |
| 응답 계보 | CoC 사건과 차량 반응의 연결 관계 | 어떤 사건에 어떤 반응이 대응하는지를 뜻하도록 설명 |
| 반복 주석 | 반복 CoC 사건 | 처음에는 `같은 행동 의도를 반복해서 나타내는 CoC`로 설명 |
| 후보 시간 의무 | 잠정 시간 조건 | 독립적인 안전 요구사항이 아니라 연구자가 설정한 분석 조건임을 함께 설명 |
| 자차 움직임 응답 증거 | 차량 반응 또는 차량 움직임에서 확인한 반응 | 측정 근거를 강조할 때만 긴 표현 사용 |
| 라우팅 | 분류 또는 처리 경로 배정 | 데이터 항목을 후속 처리 유형으로 나누는 문맥 |
| 코호트 | 분석 대상 집합 | 통계 용어가 반드시 필요한 경우에만 `코호트` 병기 |
| 스모크 테스트/출력 | 기본 동작 확인 시험/결과 | 정량 성능 결과로 오해하지 않도록 표현 |
| 음성 대조 | 오류 차단 시험 또는 잘못된 입력을 이용한 확인 | 실제 시험 목적에 따라 구체적으로 기술 |
| 합성 변이 | 인위적으로 만든 오류 사례 | 첫 등장 뒤 필요하면 `합성 오류 사례` 사용 |
| 직렬화 회귀 | 플래그와 질의 변환 과정의 회귀 시험 | 무엇의 회귀 시험인지 명시 |
| 출처 플래그 | 출처 확인 표시 | 구현 변수명을 말할 때만 영문 또는 코드 표기 유지 |

## 5. 의미 보존 경계

다음 항목은 문장 편집 과정에서 변경하지 않는다.

- 연구 질문 RQ1--RQ4의 실질적 의미
- 모든 수치, 단위, 수식, 임계값과 집계 관계
- 표ㆍ그림 번호, 레이블, 인용과 참고문헌
- 실험 조건과 결과
- 물리적 안전성이나 일반적인 CoC 충실도를 입증하지 않는다는 주장 경계
- 134개 후보의 비독립성, 125+4+5 분류, 282/1,128 직렬화 시험의 제한
- 13개 체인 결과가 별도 구현의 기본 동작 확인 결과라는 제한
- 반개구 기한 조건 `r<D`와 경계값 사례가 없다는 제한
- 상류 모델ㆍ데이터 버전의 출처 한계

문장을 쉽게 만들기 위해 정보를 삭제하지 않는다. 한 문장을 여러 문장으로
나누더라도 조건과 예외를 모두 유지한다.

## 6. 작업 순서

1. 제목과 초록 주변의 한국어 설명에서 논문의 목적을 쉬운 말로 정리한다.
2. 서론과 문제 정의에서 핵심 개념과 용어를 먼저 정의한다.
3. 데이터와 방법 절은 입력, 처리, 검증 조건 순으로 다시 정리한다.
4. 실험과 결과 절은 각 실험이 무엇을 비교했고 무엇을 확인했는지 분명히 쓴다.
5. 논의, 한계, 결론은 결과가 의미하는 것과 의미하지 않는 것을 구분한다.
6. 표와 캡션의 한국어 표현을 본문의 용어와 맞춘다.
7. 전체 용어 일관성, 수치 보존, LaTeX 구조와 PDF 배치를 검증한다.

## 7. 검증 기준

- 원본 원고와 KIEE 참조 양식의 파일 해시가 변경되지 않아야 한다.
- 영문 제목ㆍ초록ㆍ핵심어ㆍ영문 캡션ㆍ참고문헌이 변경되지 않아야 한다.
- 수치, 수식, 인용, 레이블과 연구 주장 경계가 보존되어야 한다.
- 구조 테스트 12개가 모두 통과해야 한다.
- LuaLaTeX/BibTeX 전체 빌드가 성공해야 한다.
- PDF 전 페이지에서 글자 겹침, 잘림, 표ㆍ그림 배치 오류가 없어야 한다.
- `감사`, `응답 계보`, `반복 주석`, `라우팅`, `스모크` 등의 잔여 표현은
  문맥상 꼭 필요한 경우가 아니면 없어야 한다.

## 8. 완료 산출물

- 읽기 쉬운 한국어로 수정된 KIEE 복사본
- 변경 용어와 주요 문장 개선 사례를 정리한 편집 보고서
- 빌드된 최종 PDF
- 원본 보존, 구조 검사, 빌드 및 시각 검토 결과
