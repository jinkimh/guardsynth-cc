# 국내 저널 논문 전체 논리·근거 개정 설계

## 1. 목적과 범위

`projects/sequential-coc-verification/paper/manuscript` 원고 전체를 최신 CoC/VLA 연구와 실제 실험 산출물에
맞추어 다시 구성한다. 개정의 목적은 논문을 더 강하게 보이게 만드는 것이 아니라,
각 주장이 어떤 증거에서 나왔고 어디까지 일반화될 수 있는지를 독자가 추적할 수
있게 만드는 것이다.

기존 실험 수치와 생성된 결과 파일은 변경하지 않는다. 새로운 실험을 추가하지
않으며, 다음 항목을 개정한다.

- 제목, 요약과 주요어
- 서론의 문제 간극, 연구 질문과 기여
- 최신 관련 연구와 차별성
- 데이터 생성 과정과 구성 타당성
- 문제 정의에서 사용하는 용어와 계약의 규범적 범위
- 방법과 실험의 논리적 묶음
- 결과별 허용 주장과 금지 주장
- 논의, 한계와 결론
- 참고문헌과 비교표

## 2. 새로운 중심 명제

논문 전체는 다음 명제를 중심으로 전개한다.

> 사후 생성된 CoC와 기록 자차 움직임의 일치는 인과적 정당성이나 안전성 증명이
> 아니다. 그러나 이러한 주석을 연속 시퀀스 학습 자료로 사용하려면 반복 주석,
> 응답 연결, 후보 기한과 장면 출처에 관한 해석 계약이 필요하다. 본 연구는 그
> 계약을 상태를 가진 시간 관찰자로 명시하고, 주어진 계약 아래의 정합성·민감도와
> 검토 후보를 감사한다.

이 명제는 다음 세 연구 층을 구분한다.

1. **충실도·인과성 평가:** CoC가 장면과 일치하고 trajectory에 영향을 주는가
2. **행동 개선·실행 안전:** 추론이나 행동을 어떻게 수정 또는 제한하는가
3. **본 연구의 데이터 감사:** 저장된 CoC-trajectory 주석을 어떤 시간·출처
   규칙 아래 하나의 학습 시퀀스로 해석할 수 있는가

본 연구는 1과 2를 대체하거나 해결했다고 주장하지 않는다.

## 3. 제목과 용어

### 3.1 제목

제목을 다음으로 변경한다.

> 추론 보강형 E2E 자율주행 데이터의 시간·출처 계약 감사: CoC-Nusc와 UPPAAL
> 기반 분석

기존 제목의 `판단-반응 검증`은 CoC가 온라인 제어 판단처럼 읽힐 수 있고,
`검증`은 후보 기한을 규범적 요구사항으로 오해하게 할 수 있어 사용하지 않는다.

### 3.2 핵심 용어

- `판단 사건`은 문맥에 따라 `CoC 주석 사건` 또는 `추론 주석 사건`으로 바꾼다.
- `trusted event`는 `quality-passing event` 또는 `감사 수용 사건`으로 쓴다.
  `trusted`를 유지해야 하는 코드·모델 이름에서는 “인간 정답이 아니라 검사 입력
  수용 상태”라고 명시한다.
- `obligation`은 `감사 의무(audit obligation)` 또는 `후보 시간 의무`로 쓴다.
  실제 차량의 법적·물리적 제어 의무와 구분한다.
- `response`는 `자차 움직임 응답 증거`로 쓰고 actuator command와 구분한다.
- `PASS/FAIL`은 `계약 통과/검토 후보`로 번역하며 안전/위험 레이블로 쓰지 않는다.
- `provenance`는 `출처·계보`로 통일한다.

## 4. 요약 개정

현재 요약을 약 30% 줄이고 다음 다섯 문장 기능으로 재작성한다.

1. 사후 생성된 CoC는 유용한 학습 신호이지만 판단-응답의 시간 의미론을 자동으로
   제공하지 않는다는 문제
2. CoC 주석, 자차 움직임과 출처 계층을 후보 시간 계약과 UPPAAL 관찰자로
   변환하는 방법
3. 94개 장면의 선택 과정과 134개 평가 가능 종방향 계약 결과
4. 반복 정책·탐지기 민감도, 변이 오라클과 13개 연결 체인 예비 실험이 제공하는
   핵심 정보
5. 결과가 물리 안전성이나 독립적인 CoC 충실도 증명이 아니라 학습 전 프로토콜
   감사라는 범위 제한

다음 세부 사항은 요약에서 제거한다.

- 차량 동역학 한계의 긴 열거
- 경계 음성 대조와 메타데이터 미러의 세부 과정
- `속도 변화 통과 125 + 이미 만족 4 + 검토 5`를 제외한 중복 수치
- 같은 범위 제한의 반복

## 5. 연구 질문과 주장-근거 구조

현재 다섯 연구 질문을 네 개로 재구성한다.

### RQ1 변환 타당성

> 시점이 있는 CoC 주석과 자차 움직임을 증거 수준이 명시된 시간 관찰자
> 네트워크로 변환할 수 있는가?

근거:

- `scene-0001`의 원천/도출 사건 매핑
- UPPAAL 네트워크와 질의 실행
- 알려진 합성 변이에 대한 기대 판정 일치

허용 주장: 제안 변환과 관찰자가 입력 사건 및 알려진 합성 결함을 표현·구분한다.

금지 주장: 실제 CoC 오류의 일반 검출률 또는 실제 차량 안전성을 입증한다.

### RQ2 판정 민감도와 검토 후보

> 반복 의미론, 후보 기한과 응답 탐지기 설정이 동일 기록의 감사 판정과 검토
> 우선순위를 어떻게 바꾸는가?

근거:

- 94개 장면, 403개 주석에서 290개 quality-passing, 134개 종방향 평가 가능
- 125개 속도 변화 기준 통과, 4개 이미 만족, 5개 검토 후보
- `scene-0028`, `scene-0074`의 preserve/reset 판정 반전
- 130개 사건에 대한 27개 탐지기 설정 민감도

허용 주장: 일부 판정은 반복 정책, 후보 기한과 탐지기 설정에 의존하며 이 의존성을
유형화할 수 있다.

금지 주장: 5개 후보가 unsafe trajectory이거나 CoC 오류임을 확정한다.

### RQ3 출처와 장기 에피소드

> 장면 연속성 증거와 경계 정책은 어떤 주석을 장기 학습 시퀀스로 묶을 수 있는지
어떻게 제한하는가?

근거:

- 로컬 CoC-Nusc의 장면별 시간·자세 초기화 음성 대조
- 경계 이월 합성 결함 모델
- 비공식 trainval 메타데이터 미러의 13개 엄격 체인 예비 실험
- 4개 체인 전체 질의 통과, 9개 체인 검토, 경계 predicate 위반 0,
  후보 기한 실패 8

허용 주장: 출처 증거가 없는 장면은 독립 클립으로 닫아야 하며, 연결 가능성 검사와
연결 후 시간 계약 감사는 서로 다른 단계이다.

금지 주장: 13개 체인이 공식 nuScenes 연속 시퀀스로 최종 인증되었거나, 9개 실패가
장기 주행 위험을 나타낸다.

### RQ4 정형화의 부가가치

> 결정적 타임스탬프 스크립트와 비교할 때 UPPAAL 관찰자 네트워크는 어떤 명세,
조합과 반례 추적상의 부가가치를 제공하는가?

근거:

- 13개 다중 장면 항목의 비교 가능한 Boolean 판정 13/13 일치
- 시간 관찰자, 반복 정책, 경계 정책, 변이 오라클과 교착 질의의 단일 산출물 결합

허용 주장: 단순 기한 계산은 스크립트로 재현되며 UPPAAL의 이점은 상태 생명주기와
여러 정책을 검토 가능한 명세로 조합하는 데 있다.

금지 주장: 해당 판정은 UPPAAL로만 계산할 수 있거나, 모델 체킹 사용 자체가
안전성을 높인다.

## 6. 절별 개정 설계

### 6.1 서론

서론은 다음 순서로 정리한다.

1. reasoning-augmented E2E/VLA와 CoC의 학습 역할
2. 최신 연구가 이미 다룬 충실도, CoT 개입, 센서 perturbation, 객체 인과성 및
   반사실적 교정
3. 남는 간극: 저장된 시점별 주석을 연속 학습 자료로 해석하는 시간·출처 계약
4. `scene-0001`의 반복 감속 예로 preserve/reset 차이 설명
5. CoC가 trajectory-conditioned 회고적 주석이라는 구성 타당성 경고
6. 네 연구 질문과 각 질문에 대응하는 기여

현재 서론에서 반복되는 물리 안전성 한계 문단은 한 번만 남기고 한계 절로 연결한다.
용어 표는 유지하되 `decision event`, `trusted event`, `obligation`의 표현을 새 용어에
맞춘다.

### 6.2 관련 연구

관련 연구를 네 부분으로 재작성한다.

1. **CoC 충실도와 행동 인과성:** Is VLA Reasoning Faithful?, VLADriveBench,
   Lost in Fog, Counter-nuScenes
2. **추론 기반 행동 교정과 학습:** Counterfactual VLA, C-CoT, WorkDrive
3. **실행 안전 계층과 정형 보증:** VLSA/AEGIS, UPPAAL, STL, RSS,
   Scenic/VerifAI, reachability
4. **본 연구의 위치:** 모델 재추론이나 행동 수정이 아닌 저장된 주석의 시간·출처
   감사

VLSA/AEGIS는 로봇 조작 연구로 정확히 기술한다. 최신 논문과의 차이는 `다루지
않는다`고 단정하기보다 “보고된 주된 평가 단위가 다르다”고 신중하게 쓴다.

비교표의 열은 다음으로 바꾼다.

- 연구군
- 주된 평가/개입 단위
- 모델 재추론 또는 입력 개입
- 상태를 가진 반복·기한 계약
- 장면 출처 검사
- 주장 범위

### 6.3 데이터와 증거 수준

가장 앞에 다음 구성 타당성 문단을 추가한다.

- CoC는 기록 trajectory에서 meta-action을 먼저 추출한 뒤 영상·trajectory와 함께
  생성된다.
- 따라서 CoC와 같은 trajectory의 방향 일치는 독립적인 인과 검증이 아니며 높은
  통과율도 어느 정도 생성 절차로 예상된다.
- 본 감사가 추가하는 정보는 동일 샘플의 내용 재확인이 아니라, 시점별 주석이
  반복·기한·응답 계보·경계 정책 아래 일관된 에피소드로 조합되는지 여부이다.

데이터 선택 흐름을 명시한다.

```text
403 annotations
  -> 290 machine quality-passing annotations
  -> 134 applicable longitudinal audit contracts
  -> 130 speed-detector cases + 4 already-satisfied cases
```

`quality_pass`는 인간 gold가 아니라 모델 생성 신호임을 표와 본문에서 일관되게
유지한다. 5개 후보의 영상 확인은 독립 인간 검토가 아니라 네 개 전방 카메라
표본 프레임에 기반한 AI 시각 triage였음을 명시한다.

### 6.4 문제 정의

식의 $D_i$를 `candidate deadline`으로 일관되게 정의한다. 식의 만족은 규범적 안전
의무 준수가 아니라 선택한 감사 계약 아래의 정합성이다.

`의무`의 세 층을 구분한다.

1. 주석에서 파싱한 행동 의도
2. 연구자가 선택한 후보 시간 계약
3. 자차 움직임에서 도출한 응답 증거

이 세 요소 중 어느 것도 독립적인 실제 제어 명령이 아니다. preserve/reset/dedup은
정답 후보가 아니라 주석 정책 대안이며, 판정 반전은 정책 명세 필요성을 보여주는
민감도 결과로 정의한다.

### 6.5 제안 방법

방법은 다음 네 독립 구성요소로 설명한다.

1. **증거 수집기:** CoC timestamp, text, quality와 ego-motion을 읽는다.
2. **계약 컴파일러:** 의도, 후보 기한, 반복 정책과 응답 predicate를 생성한다.
3. **상태 관찰자:** 의무 생명주기, 응답 매칭, 저품질 덮어쓰기와 장면 경계를
   감시한다.
4. **결과 router:** 계약 통과, 민감도·의미론 의존 후보, 출처 불충분과 합성 변이를
   서로 다른 용도로 분류한다.

UPPAAL 원천 오토마타는 환경이나 행동을 탐색하지 않고 결정적 사건열을 재생한다는
점을 방법 절 초반에 밝힌다. 변이 오라클은 checker의 내부 타당성 검사이며 현실
결함 빈도 추정이 아니다.

### 6.6 실험 설계

기존 8개 실험을 다음 세 블록으로 묶는다.

#### A. 변환·검사기 타당성

- `scene-0001` 변환
- 알려진 합성 변이
- 합성 다단계 프로토콜 표현력
- 스크립트 기준선

#### B. 일괄 감사와 민감도

- 94개 장면 일괄 선별
- 5개 검토 후보 집중 분석
- 후보 기한, 반복 의미론, 27개 탐지기 설정

#### C. 출처와 에피소드 확장

- 로컬 장면 독립성 감사
- 경계 이월 음성 대조
- 메타데이터 미러 기반 13개 체인 예비 실험

각 블록의 끝에 대응 RQ, 독립변수/고정조건, 출력과 허용 주장을 명시한다.

### 6.7 실험 결과

결과는 RQ 순서로 배치한다. 첫 표로 다음 주장-근거 행렬을 둔다.

| 결과 | 직접 지지하는 주장 | 지지하지 않는 주장 |
|---|---|---|
| 합성 변이 기대 판정 일치 | 관찰자와 질의가 삽입 결함을 구분 | 실제 오류 검출률 |
| 125+4 통과, 5 후보 | 선택 계약 아래 audit routing 가능 | 안전/위험 데이터 비율 |
| preserve/reset 반전 | 반복 정책을 명시해야 판정이 결정됨 | 어느 정책이 실제로 옳음 |
| detector 민감도 | 응답 증거 판정의 threshold 의존성 | actuator response 실패 |
| 13개 체인 pilot | 연결 후보에서도 별도 시간 감사 가능 | 공식 장기 데이터셋 일반화 |
| script 13/13 일치 | 단순 판정은 script로 재현 가능 | UPPAAL의 수치적 우월성 |

다음 표현을 수정한다.

- `발견된 오류` -> `감사 후보` 또는 `합성 실패 양상`
- `데이터 처리 정책의 결함` -> `비원자적 중복 제거가 만들 수 있는 합성 계보 실패`
- `안전한/위험한 샘플` -> `계약 통과/검토 후보`
- `검출력` -> 합성 변이에 대해서만 `mutation sensitivity` 또는 `기대 판정 일치`

13개 체인 결과는 반드시
`artifacts/results/public/multiscene-chain/uppaal-loop-batch-all-strict-1s.json`
을 근거로 한다. 이전 10개 부분집합 summary와 혼동하지 않는다.

과속방지턱·주차 차량 등의 단어 패턴 결과는 산출물 간 집계 정의가 일관되지 않고
표본도 작으므로 본문의 인과적 또는 정량적 결과에서 제거하거나 탐색적 관찰 한
문장으로만 남긴다.

### 6.8 논의와 활용

논의는 다음 세 질문만 답한다.

1. 이 감사가 학습 데이터 준비에서 무엇을 바꾸는가?
2. 왜 통과와 실패 모두 안전 레이블이 아닌가?
3. 왜 일반 스크립트 대신 정형 관찰자 명세를 유지할 가치가 있는가?

학습 활용은 실제 효과를 실험하지 않았으므로 `학습 데이터 선별 효과`가 아니라
`제안 routing policy`로 표현한다. 통과 샘플도 `약한 유지 후보`, 실패 샘플도
`검토 후보`이다. 폐루프 평가와 물리 분석은 후속 계층으로만 둔다.

### 6.9 한계와 타당성 위협

한계 절을 다음 순서로 재구성한다.

1. **구성 타당성:** CoC가 trajectory-conditioned 회고적 주석이며 독립 판단이 아님
2. **측정 타당성:** ego speed 기반 응답은 actuator action이나 collision risk가 아님
3. **계약 타당성:** $D=3$s와 반복 정책은 규범 요구사항이 아닌 분석 설정
4. **내적 타당성:** intent parser, quality gate, already-satisfied rule과 detector
   threshold에 결과가 의존
5. **외적 타당성:** 94개 장면의 선택된 134개 종방향 계약에 한정
6. **검토 타당성:** 후보 영상 triage가 독립 인간 gold가 아님
7. **출처 타당성:** 13개 체인이 비공식 metadata mirror에 기반
8. **형식화 한계:** 결정적 replay이며 실제 closed-loop environment를 탐색하지 않음

현재 여러 절에 반복된 물리 안전성 한계를 이 절에서 체계적으로 정리하고, 앞에서는
짧게 참조한다.

### 6.10 결론

결론은 세 문단으로 줄인다.

1. 문제와 방법
2. 가장 직접적인 세 결과: 정책 민감도, 유형화된 검토 후보, 출처가 있는 episode
   감사
3. 무엇을 보이지 않았는지와 다음 검증 계층

상세 수치를 요약과 결과에서 이미 제시하므로 결론에서는 한 번만 압축해 언급한다.

## 8. 전체 주장-증거 가드레일

### 원고가 주장할 수 있는 것

- CoC 주석과 자차 움직임을 상태를 가진 후보 시간 계약으로 형식화할 수 있다.
- 반복 정책, 후보 기한과 응답 탐지기가 감사 판정을 바꿀 수 있다.
- 선택한 설정 아래 검토 후보를 유형화하고 후속 검토 경로를 제안할 수 있다.
- 출처 증거가 없는 장면을 연결하지 않는 정책을 정형 속성으로 표현할 수 있다.
- 결정적 replay에서도 UPPAAL은 여러 정책과 관찰자, 합성 변이를 한 명세로 묶는다.

### 원고가 주장하면 안 되는 것

- CoC의 일반적 faithfulness 또는 causal correctness를 검증했다.
- 통과 샘플이 안전하고 검토 후보가 위험하다.
- $D=3$s가 법규 또는 차량 동역학에서 도출된 안전 기한이다.
- ego-speed response가 brake/throttle command를 나타낸다.
- 합성 변이 결과가 실제 데이터 오류 빈도나 검출률을 나타낸다.
- 13개 metadata-mirror 체인이 공식 장기 driving sequence gold set이다.
- UPPAAL 사용이 스크립트보다 더 정확하거나 차량 안전성을 보장한다.
- 제안 routing policy가 실제 E2E 학습 성능 또는 collision을 개선했다.

## 9. 검증 기준

- 요약 길이가 현재보다 25--35% 감소한다.
- 제목, 요약, RQ, 실험과 결론이 동일한 중심 명제를 사용한다.
- 네 RQ 각각에 대응하는 실험·결과·제한이 추적 가능하다.
- 403 -> 290 -> 134 -> 130+4 선택 흐름이 모든 절에서 일치한다.
- 134 = 125 + 4 + 5 계산이 모든 절에서 일치한다.
- 282개 모델은 94개 장면의 baseline/provenance/response 변형이며,
  1,128개는 282×4 질의임을 명확히 한다.
- 13개 strict chain 결과는 4개 체인 전체 질의 통과, 9개 체인 검토,
  후보 기한 실패 8, 응답 도달성 실패 7, 경계 predicate 위반 0으로 일치한다.
- 최신 연구 8개가 실제로 인용되고 참고문헌에 존재한다.
- `first`, `최초`, `유일` 같은 우선권 주장이 없다.
- `unsafe`, `collision`, `safety guarantee`가 본 연구 결과처럼 표현되지 않는다.
- 미정의 인용·참조, 치명적 LaTeX 오류와 overfull box가 없다.
- 재생성된 PDF에서 표·그림과 문장이 겹치거나 잘리지 않는다.
