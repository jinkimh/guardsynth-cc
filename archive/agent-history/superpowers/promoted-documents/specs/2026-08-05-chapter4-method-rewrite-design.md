# 4장 연구 방법 개정 설계

## 목적

4장을 처음 읽는 독자도 제안 방법의 입력, 학습, 궤적 선택, 독립 검증 및 평가 흐름을 이해할 수 있도록 다시 작성한다. 한국어 설명을 우선하고, 필요한 영어 용어는 처음 한 번만 함께 적는다.

## 구성

1. 전체 흐름: 장면과 CoC 및 후보 입력부터 독립 검증까지 그림 2의 순서로 설명한다.
2. 입력 표현: 기존 CoC와 실행 가드가 결합되는 방식 및 다섯 비교 조건의 목적을 설명한다.
3. 쌍대 계약: 동일 장면에서 가드만 바꾸는 이유와 그림 3의 판정 논리를 설명한다.
4. 후보 표식: A/B/C/D는 고정 행동이 아닌 임시 이름이며, 행동 역할과의 대응을 매 장면 바꾼다는 점을 표로 설명한다.
5. 모델 학습: Qwen3-VL-2B-Instruct와 LoRA의 역할, 입력과 출력 및 정답 생성 절차를 설명한다.
6. 독립 검증과 지표: 물리량을 별도 계산기가 판정하는 이유와 각 평가 지표를 표로 정의한다.
7. 적용 범위: 학습된 가드 준수와 실제 실행 단계의 안전 보장을 구분한다.

## 용어 원칙

- `requirement-only`는 `요구사항 전용형`으로 쓴다.
- `inline constraint`는 `CoC 통합형`으로 쓴다.
- `separate natural-language guard`는 `가드 분리형`으로 쓴다.
- `shuffled guard`는 `대응을 섞은 가드`로 쓴다.
- `logic guard`는 `논리식 가드`로 쓴다.
- `verifier`는 처음에 `독립 검증기(verifier)`로 정의한 뒤 `검증기`로 쓴다.
- `permissive/restrictive contract`는 `완화 계약/엄격 계약`으로 쓴다.

## 혼동 방지

궤적 후보 A/B/C/D와 보조 실험 조건 A/B/C/D가 겹치지 않도록, 보조 실험 조건은 `상태 전용`, `상태+CoC`, `동적 계약`, `단조 단계 계약`, `계약+차단장치`라는 서술형 이름으로 바꾼다.

## 검증 기준

- 4장이 3장의 문제 정의와 5장의 실험 설계를 연결한다.
- A/B/C/D의 의미와 표식 순환 이유가 표와 본문에 모두 명시된다.
- 모델이 연속 궤적을 새로 생성하는 것이 아니라 주어진 후보를 선택한다는 점이 분명하다.
- 독립 검증기의 입력 물리량과 평가 지표가 정의된다.
- 실제 차량 안전 보장이 아니라 제한된 후보 선택 평가임을 명시한다.
- 전체 LaTeX 빌드에 오류, 미정의 참조 및 여백 초과가 없다.
