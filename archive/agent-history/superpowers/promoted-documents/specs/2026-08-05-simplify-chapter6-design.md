# 6장 논의 설명 개선 설계

## 목표

4–5장에서 사용한 용어와 실험 결과를 그대로 이어 받아, 독자가 6장의 해석과 연구 한계를 새로운 영어 용어 없이 이해하도록 한다.

## 구성

기존 일곱 논점은 유지하되 제목과 설명 순서를 다음과 같이 바꾼다.

1. CoC와 실행 가드가 각각 맡는 역할
2. CoC 통합형이 높은 결과를 보인 이유
3. 수치 조건을 독립 검증기가 다시 확인해야 하는 이유
4. 학습된 가드와 실행 차단장치의 차이
5. 주 실험이 실제로 확인한 범위
6. 결과를 해석할 때의 실험적 한계
7. Alpamayo-R1과 실제 도로로 확장하기 위해 필요한 검증

각 소절은 5장의 관련 결과를 먼저 말하고, 그 결과가 뜻하는 것과 뜻하지 않는 것을 이어서 설명한다.

## 용어

- `inline 자연어`는 `CoC 통합형`으로 쓴다.
- `separate/logic`은 `가드 분리형/논리식 가드`로 쓴다.
- `runtime verifier/shield`는 `실행 중 독립 검증기/차단장치`로 쓴다.
- `construct, internal, external validity`는 각각 `주 실험이 확인한 범위`, `결과 해석의 한계`, `실제 적용 범위`로 설명한다.
- 계약 정보가 오래된 경우는 `현재 상황보다 늦게 도착한 계약`으로 설명한다.

## 그림 7

영어로 된 네 단계를 4–5장의 용어로 바꾼다.

1. 자연어 Safety-Constrained CoC
2. 실행 가드 변환: 조건 종류, 비교 방향, 값, 단위, 대체 행동
3. 단위 통일: 600 cm → 6.0 m
4. 독립 검증기 또는 차단장치: 거리, 속도, 시간 조건 확인

하단에는 `모델은 목표와 가드를 해석하고, 검증기는 수치 경계를 확인한다`고 명시한다.

## 유지할 주장과 한계

- 기존 CoC가 위험하다는 주장을 하지 않는다.
- 자연어가 논리식보다 본질적으로 우수하다고 주장하지 않는다.
- 작은 VLM의 후보 선택 결과를 Alpamayo-R1의 연속 궤적이나 실제 차량 안전으로 확대하지 않는다.
- 실제 적용에는 센서 근거, 보행자·차량의 위치 관계, 충돌 위험, 계약 시점과 독립된 정답 판정이 필요하다.
