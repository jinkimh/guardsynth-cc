# 세 리뷰어 심사 대응 재분석·재실험 설계 V01

> 실행 담당자는 검토된 계획을 기준으로 `superpowers:executing-plans`를 적용한다. 이 문서는 연구 평가 계획이며, 구현 코드는 별도 작업 단계에서 작성한다. 독립 평가자란 실제 역할과 자료 접근이 분리된 검토자를 뜻하며, 에이전트 호출 수로 독립성을 주장하지 않는다.

**Goal:** 기존 결과를 최대한 재사용하고 필요한 독립 시험만 추가하여 세 리뷰어의 방법론·재현성·평가·서술 지적에 근거로 답한다.

**Architecture:** 기존 결과의 재분석, 규칙 추출과 상태전이 명세, 자연 CoC 기반 가상 오류 주입 평가를 분리한다. 구조화 입력의 검사 성능과 자연어 추출을 포함한 전체 과정, 주석 오류와 검사기 처리 오류, 자연 표본과 합성 시험은 각각 별도 결과로 보고한다.

**Tech Stack:** 기존 Python 검사기·집계 코드, UPPAAL/verifyta, JSON/JSONL/CSV, LaTeX. 모델 재학습·새 LLM API·GPU 실험은 기본 계획에 없다.

**Spec:** 아래 R1·R2·R3 파일, 현재 10쪽 원고 및 `SQ-M05` 심사 대응 마일스톤.

- 소유 프로젝트: `sequential-coc-verification`
- 작성 기준일: 2026-09-30
- 반영한 사용자 결정: 자연 CoC에 다양한 가상 오류를 주입하여 탐지 성능을 평가하는 방향에 합의. 사용자의 단계별 실행 요청에 따라 계획을 승격함. 사람 검토 배정과 자료 적격성 확인은 실행 전제이며 자동 완료로 취급하지 않음.
- 문서 상태: `ACTIVE` — 사용자 검토 및 단계별 실행 요청에 따라 E0부터 착수; 사람 독립 판정은 별도 필요
- 기준 원고: `projects/03-sequential-coc-verification/paper/manuscript/latex-kiee-review-2022-coc-audit-10pages/`
- 상위 계획: `projects/03-sequential-coc-verification/docs/plans/01_RESEARCH_PLAN_V01.md`
- 범위 제어: `02_PROJECT_MILESTONES.md`의 `SQ-M05`; `SQ-M06` 학습·폐루프 확장을 이 계획에 포함하지 않는다.
- 제출 기한과 평가자 일정은 미확인이다. 아래 작업일은 순수 작업량 추정이며 제출일 약속이 아니다.

## 1. 기본 결정과 완료의 의미

1. 기존 논문과 과거 결과는 보존한다. 재실험은 새로운 run ID로 저장한다.
2. 기존 40쌍은 규칙 실행 회귀시험이다. 새로운 독립 평가로 이름을 바꾸지 않는다.
3. 기존 27장면은 재분석·지침 보완에 사용한다. 같은 사례를 다시 본 판정은 새 독립 표본으로 계산하지 않는다.
4. 자연 모순을 발견하지 못하면 recall/F1을 임의로 계산하지 않는다. 데이터 부족에 따른 미산출과 방법 실패를 구분한다.
5. 100% 정확도, 높은 κ, 제안법의 우위가 작업 완료 조건은 아니다. 고정된 프로토콜의 완전한 실행과 실패를 포함한 보고가 완료 조건이다.
6. 판정 규칙·코드·시험 정답을 고정한 뒤 오류를 발견하면 첫 결과를 보존한다. 수정 후 같은 시험의 결과는 재시험으로 표시하며 새 독립 평가로 부르지 않는다.
7. 원자료·검토자 정보는 기존 restricted 분류를 유지한다. 공개는 익명 집계·코드·배포가 허용된 자료에 한하며 이번 계획 작성은 외부 공개를 실행하지 않는다.
8. 확장 비교나 새 자료 수집보다 기존 근거 복원과 독립성 확보를 우선한다.

## 3. 단계별 실행 계획

### E0. 근거 복원과 실행 환경 고정 — 필수, 새로운 실험 아님

**입력:** 세 심사 의견, 10쪽 원고, 위 근거 목록, 기존 코드·테스트.

- [ ] 파일 존재·해시, 실행 명령, Python·UPPAAL 버전, 원고 버전 및 기준 코드 상태를 기록한다.
- [ ] 743장면 전체 원문에 실제 접근 가능한지 확인한다. 94장면·27검토 장면·개발/규칙 조정 사용 장면의 목록을 복원한다. 미확인 이력은 `UNKNOWN_EXPOSURE`로 둔다.
- [ ] 기존 검사·compiler·UPPAAL 테스트를 재실행한다. 기존 출력의 불일치를 기록하고 재현 실패를 조용히 수정하여 덮지 않는다.
- [ ] CoC 생성 모델/version·prompt·quality score·선정 기준을 upstream 기록과 코드에서 추적한다. 복원하지 못한 값은 `미기록`으로 표시한다.
- [ ] `artifact_inventory.csv`, `provenance_inventory.csv`, `exposure_manifest.json`을 생성한다.

**완료 기준:** 각 근거가 `직접 재사용 / 재집계 / 재실행 필요 / 근거 부족` 중 하나로 분류되고, 숫자와 출처의 연결이 명확하다.

**예상 작업:** 0.5–1일. 다음 작업은 E1·E2이며, E0만으로 신규 독립 평가가 완료된 것으로 표시하지 않는다.

### E1. 기존 평가 재분석 — 필수, 추가 라벨링 전 수행

#### E1-A. 네 평가자의 판정과 합의 기록

- [ ] 4명×27장면 CSV를 검토 ID로 정렬하고 기존 κ·평균 쌍별 일치율을 재계산한다. 원본 라벨은 변경하지 않는다.
- [ ] 평가자별 판정 분포와 항목별 투표 패턴을 보고한다. 텍스트 일관성 23/27 불일치와 평균 쌍별 일치율 약 0.407을 원자료로 검증한다.
- [ ] 불일치 원인을 `모순 대 외부 증거 부족`, `적용 여부`, `행동 분할·순서`, `문장 자체 모호성`, `기록 부족`으로 분류한다. 유형별 건수와 중복 분류 여부를 명시한다.
- [ ] 원본 메모→합의 판정 연결을 확인한다. 합의 사유가 없으면 현재 해석과 당시 기록을 구분하고 당시 절차를 추정하여 기재하지 않는다.
- [ ] 기존 검토 지침의 버전, 검토자의 실제 자격·교육·독립 판정 절차는 확인된 사실만 기록한다.

#### E1-B. 미상 18장면 및 궤적 불일치 7장면

- [ ] 기존 27장면 전체에 대해 `scene_id, text_verdict, trajectory_verdict, reason, evidence_source, missing_evidence, followup`을 기록한다.
- [ ] 장면 판정과 사건 판정의 집계 규칙을 명시한다. 사건 하나의 Unknown이 장면 전체를 Unknown으로 만드는지 코드로 확인한다.
- [ ] 미상 18건을 단순한 ‘객체 정보 부족’으로 일괄 설명하지 않고 실제 저장 사유·원문·코드를 연결한다.
- [ ] 2/7/18 합계 및 전체 궤적 자료와의 연결을 검증한다. 7건은 물리적 위험이나 문장 모순의 자연 정답으로 전환하지 않는다.

#### E1-C. 선정·임계값·사후 규칙

- [ ] 자동 후보 15장면과 비교 12장면의 정규식·장면당 선택·매칭 규칙을 복원한다.
- [ ] 403→290→134와 제외 156건, 130+4 및 125+4+5의 각 분모·중복 단위를 재검증한다.
- [ ] 27설정에서 항상 반응 검출 72건, 일부 설정 검출 57건, 항상 미검출 1건인지 확인한다. 기존 ‘58건 모두 설정에 따라 변화’ 표현은 집계 근거에 따라 바로잡는다.
- [ ] STOP/YIELD의 0.5 m/s 사후 규칙 도입 전후 8→5 후보 변화와 해당 사건을 구분한다. 사후 분석임을 유지한다.
- [ ] 기존 결과를 재구성할 수 있으면 전체 임계값 실험을 새로 하지 않는다. 누락된 행만 같은 조건으로 재실행하고 실행 시점을 표시한다.

**출력:** `reviewer_distribution.csv`, `disagreement_cases.csv`, `scene_evidence_cases.csv`, `selection_flow.csv`, `threshold_summary.csv`.

**완료 기준:** 새 사람 라벨 없이 답할 수 있는 R1/R3 의견에 사례와 재현 가능한 표가 연결된다. κ가 높아지는 것은 완료 조건이 아니다.

**예상 작업:** 1–2일.

### E2. 의미·추출·상태전이 명세 확정 — 필수, 새로운 벤치마크 아님

**입력 코드:** `contract_ir.py`, `contract_compiler.py`, `stateful_checker.py`, `event_local_checker.py`, `uppaal_generator.py`, `run_uppaal.py`, 기존 `tests/`.

- [ ] P1–P3의 주석/구조화 사건 위반과 P4의 검사기 상태 갱신 오류를 별도 평가 대상으로 정의한다. 기존 40쌍도 30쌍과 10쌍에 해당하는지 실제 타입을 확인하여 분리한다.
- [ ] 추출이 규칙 기반임을 명시하고 행동 사전, 조건 연결어, 동의·부정·복합행동 처리와 지원하지 않는 표현을 목록화한다. 구현되지 않은 언어 현상까지 지원한다고 서술하지 않는다.
- [ ] 실제 자연 CoC 4–6개를 사용해 `원문 span → 구조화 필드 → 증거 출처 → checker input → 판정`을 제시한다. 예시는 E3 평가에서 제외한다.
- [ ] 요구 생성/유지/해제 순서, True/False/Unknown, 동시 활성 요구의 식별·정렬·첫 위반 선택, 장면 종료·경계, 중복 사건 처리의 상태전이표를 코드와 대조한다.
- [ ] Unknown을 실제 조건 False로 치환하지 않는다. 종료 미상 상태의 행동을 어디까지 CONTRADICTION으로 판정하는지는 기존 구현과 명세를 대조하고 증거 강도를 명시한다. 미해결 요구가 있다는 이유만으로 물리적 위반을 단정하지 않는다.
- [ ] 불명확한 부분은 시험 결과를 보기 전에 판단 기준을 결정하고 기록한다. 역사적 구현과 달라지면 변경점·이유·baseline 재실행 범위를 남긴다.
- [ ] Python 상태/분기↔UPPAAL 상태/전이/질의/trace 필드의 대응표를 작성한다. 중앙 모델과 반응시간 보조 모델을 구분한다.
- [ ] 현재 테스트가 포괄하지 못하는 경계조건만 regression test로 보완한다. 결과를 본 뒤 수정한 테스트는 독립 평가에 포함하지 않는다.

**출력:** `semantics_spec.md`, `source_to_input_examples.jsonl`, `implementation_mapping.csv`, 기준 코드·명세 해시.

**완료 기준:** 각 입력 조건의 기대 판정·근거·상태 갱신이 검토 가능하고, 명세와 구현 불일치가 숨겨져 있지 않다. 이 시점 이후 E3/E4용 코드·판정 규칙을 고정한다.

**예상 작업:** 1–2일.

### E3. 보유 자연 자료의 독립 재검토 및 추출 평가 — 권장 기본 범위, 실제 평가자 필요

**목적:** 새 데이터 수집 대신 보유 원문을 활용해 지침 재현성과 자연어 변환을 평가한다. 자연 모순 발견을 성공 조건으로 삼지 않는다.

**분할·규모:**

- 기존 27장면 중 불일치 유형을 포함한 6장면을 지침 연습에만 사용한다. 새로운 성능 표본으로 세지 않는다.
- E0에서 이전 개발·검토 사용을 확인한 장면과 E2 예시를 제외한 장면 중 최소 2개 CoC가 있는 장면을 모집단으로 삼는다. 동일 원본 장면의 파생본과 확인 가능한 연속 구간은 같은 분할에 묶는다.
- 기본 목표는 **24장면**, 선정 seed `20260930`. 정렬된 적격 장면 목록에서 비복원 무작위 선정하고 목록·해시·알고리즘을 고정한다. 결과를 보고 모순 장면으로 교체하지 않는다.
- 적격 표본이 24개보다 적으면 전부 사용하고 규모와 부족 원인을 보고한다. 사용 이력이 불명확한 자료만 남으면 ‘새 사람 검토’로만 부르고 개발 독립성을 주장하지 않는다.
- 장면 일관성 검토에는 해당 장면의 전체 CoC 순서를 제공한다. 추출 평가는 같은 장면에서 최대 4개 원문을 사전 선정해 총 최대 **96문장**으로 제한한다. 단일 문장 정확도와 전체 장면 판정을 혼동하지 않는다.

**역할·블라인드:**

- 두 실제 검토자가 검사기 출력 없이 독립 판정한다. 서로의 답과 합의 라벨을 처음부터 보여주지 않는다.
- 검토 지침·연습 완료를 기록한 후 평가 라벨을 수집한다. 불일치는 제3자 검토를 우선하되 불가능하면 두 검토자 합의 방식이라고 명시한다.
- 모순·일관됨·외부 증거 부족·문장 모호·적용 대상 아님을 구분한다. 원문, 원문 span 및 판정 이유를 기록한다.
- 외부 증거가 필요한 장면을 이미지 없이 텍스트 정답으로 강제 판정하지 않는다. 영상 평가는 별도 범위로 둔다.

**절차:**

- [ ] E1을 바탕으로 지침을 보완하고 6장면에서 연습한다. 연습 결과는 평가와 분리한다.
- [ ] 장면 목록, 추출 문장 목록과 지침을 고정한다.
- [ ] 독립 원시 판정을 보존한 뒤 일치도·판정 분포를 산출하고 조정 근거를 기록한다.
- [ ] 행동·요구·종료 조건·선행조건·근거 span·불확실성 필드의 구조화 정답을 작성한다. 기존 설문은 파서 평가가 아니므로 자동으로 추출 정답으로 전용하지 않는다.
- [ ] 사람이 확인한 구조화 입력의 검사 결과와 자동 추출 입력의 검사 결과를 분리한다.

**지표:**

- 합의 전 κ, 평균 쌍별 일치율, 범주별 분포 및 해석 한계.
- 필드별 일치율, 모든 필드 일치 비율, 지원/실패/Unknown 비율과 오류 사례. 추출 실패를 분모에서 제거하지 않는다.
- 자연 판정은 gold와 prediction의 전체 범주 교차표를 보고한다. 이진 confusion matrix는 명확히 consistent/inconsistent인 gold에 한정하고 예측 Unknown은 별도로 표시하여 성능이 좋아 보이도록 제외하지 않는다.
- 평가 가능 비율과 abstention을 함께 제시한다. recall에서는 실제 양성을 Unknown으로 보류한 경우도 미검출로 집계한 값을 별도 명시한다.
- 양성 0이면 recall은 미정의이며 해당 검출 F1은 미산출 사유를 표기한다. 예측 양성 0의 precision도 미정의로 보고한다. 자연 오류율을 전체 데이터셋에 일반화하지 않는다.
- 성능 차이와 추출 집계의 95% 구간은 동일 장면 내 문장 의존성을 고려해 장면 단위 재표집 2,000회(seed `20260930`)로 계산한다. 분모 0인 재표집 비율을 보고하며 안정적으로 정의되지 않으면 구간을 제시하지 않는다. 소표본 탐색 결과로 해석한다.

**출력:** `sampling_manifest.json`, `annotation_guideline.md`, 원본 익명 reviewer CSV, `adjudication.csv`, `extraction_gold.jsonl`, `natural_evaluation.json`, `extraction_evaluation.json`.

**완료 기준:** 실제 독립 판정과 추출 정답이 확보되고 실패·미상 포함 전체 표본이 보고된다. 높은 일치도나 양성 발견은 요구하지 않는다.

**대체 경로:** 사람 검토를 확보하지 못하면 E1의 기존 자료 분석까지만 수행한 상태를 명시한다. R1-M3의 재평가와 R3의 자연 독립 평가 요구를 완료했다고 표시하지 않으며, 제한된 feasibility 주장과 미충족 사유로 답한다.

**예상 작업:** 패킷·집계 1–2일 + 사람 검토 일정. 24장면은 비용을 제한한 초기 규모이며 검정력 보장 수치가 아니다.

### E4. 자연 CoC 기반 가상 오류 주입과 탐지 성능 평가 — 필수 신규 핵심

**합의된 방향:** 보유한 자연 CoC에 다양한 오류를 의도적으로 주입하고 탐지 성능을 평가한다. 현재 검사기가 발견하는 사례만 고르지 않는다. 보고 명칭은 **자연 CoC 기반 인위적 오류 주입 평가**이며, 자연 발생 오류 검출 성능과 구분한다.

**기존 설계 대체:** 완전히 새로 작성하는 합성 48시퀀스 계획을 아래 원문 기반 대응 평가로 대체한다. 기존 40쌍은 회귀시험으로 유지한다. E3의 원문·사람 검토·추출 정답을 재사용해 별도 자료 구축 부담을 줄인다.

#### E4-A. 원문 선정과 평가 묶음

- E3에서 고정한 24장면의 전체 CoC 시퀀스를 원문 대조군으로 먼저 평가한다. 실제 판정은 consistent/contradiction/unknown 등을 사람 검토로 확인하며 원문이라는 이유만으로 정상으로 간주하지 않는다.
- 그중 사람이 일관됨으로 확인하고 아래 오류 연산이 의미 있게 적용되는 장면 B개(B≤24)를 변형 기준으로 삼는다. 적용 가능 여부는 문장·명세·객체 식별 근거로 결정하며 검사기 결과를 사용하지 않는다.
- 각 적격 원문에서 **모순 주입 2종 + 의미를 유지하는 정상 변형 1종 + 증거 누락/미상 변형 1종**을 만든다. 전체 예산은 `원문 24개 + 4B개 변형`, 최대 **120개 시퀀스**다. 이는 120개의 독립 자연 장면이 아니다.
- 적용 가능한 오류가 부족하면 유형별 실제 수와 미구성 이유를 보고한다. 규모를 맞추려고 원문에 없던 행위자·계약을 만들어 넣거나, 검사기 검출률을 본 뒤 원문을 교체하지 않는다.
- 원문 모순·Unknown은 원문 평가에 보존하고 정상 기준 변형에서 제외한 이유를 기록한다. 순수 작성 사례가 경계 시험에 필요하면 별도 합성 집합으로 표시한다.
- 원문과 모든 파생 변형은 동일 split·동일 cluster에 둔다. E3 고정 자료는 지침·compiler 조정에 사용하지 않고, 개발은 기존 27장면 및 기존 시험에서 끝낸다.

#### E4-B. 오류 유형과 대조군

| ID | 주입할 변경 | 독립 정답의 조건 | 평가 역할 |
|---|---|---|---|
| M1 | 아직 유지 중인 정지·양보 요구에 반하는 진행 행동 | 종료 조건이 **충족되지 않았다는 명시적 근거**와 진행 행동이 함께 있어야 함 | 유지 요구와 행동 충돌 |
| M2 | 종료 조건이 거짓인데 요구를 끝냈다고 기술 | 동일 조건·대상에 대해 False와 해제가 명시되어야 함 | 조기 해제 |
| M3 | 명시한 선후 관계를 거꾸로 실행 | 원문의 순서 제약과 변경한 사건 순서가 명확히 충돌 | 행동 순서 위반 |
| M4 | 필수 선행 행동을 수행하지 않았다고 명시하면서 후속 행동 수행 | 선행 행동의 단순 생략이 아니라 **미수행 근거**가 있어야 함 | 선행조건 위반 |
| M5 | 다른 객체의 해제 증거로 현재 객체에 대한 요구를 해제·진행 | 서로 다른 대상이 원문에 식별되고 원래 대상의 미해제가 명시됨 | 대상별 요구 연결 오류 |
| M6 | 여러 활성 요구 중 일부만 해제되었는데 모두 해제된 것으로 진행 | 남은 요구의 적용 대상·조건과 실제 미충족이 명확함 | 복수 요구 유지 오류 |
| C1 | 의미를 유지하는 동의 표현·불필요한 서술 변경 | 의무·조건·행동 순서·대상이 보존됨 | 정상 변형 오경보 대조군 |
| U1 | 종료 여부에 대한 증거를 제거 | 명시적인 모순도 종료 확인도 없어야 함 | 증거 부족을 모순으로 오인하는지 검사 |

M1–M6은 P1–P3에 대응하는 세부 양상 및 범위 확인용 도전 유형이며, 여섯 가지 모두가 현 구현에서 지원된다고 가정하지 않는다. E2에서 schema와 구현의 지원 범위를 먼저 고정한다. 대상 식별·복수 요구처럼 표현 자체가 불가능한 유형은 `미지원 도전 사례`로 분리하고 지원 범위의 분모와 함께 보고한다. 미지원·추출 실패를 전체 과정 결과에서 숨기지 않으며 결과를 본 후 ‘범위 밖’으로 재분류하지 않는다.

유형별 적격 원문을 검사기 실행 전에 목록화하고, 두 모순 변형은 가능한 서로 다른 유형으로 배정한다. 한 유형의 표현만 반복하지 않도록 원문 대상·문장 구조를 분산한다. 사건 간격(중간 사건 0/1/3/5)과 활성 요구 수(1/2)는 보조 난이도 조건으로 사용할 수 있으나, 추가한 사건도 인위적 편집으로 명시한다. 추가 변형은 최대 120개 예산 안에서 사전 배정하며 성능이 나온 뒤 증량하지 않는다.

**설명용 예시 — 실제 자료 인용이나 평가 정답으로 사용하지 않음:**

- 기준: “보행자가 통과할 때까지 정지한다.” → “보행자가 통과했으므로 진행한다.”
- M1: “보행자가 통과할 때까지 정지한다.” → “보행자가 아직 횡단 중이지만 진행한다.”
- U1: “보행자가 통과할 때까지 정지한다.” → “이제 진행한다.”
- 마지막 사례의 통과 증거 부재는 미통과 증거가 아니다. 물리적 위험 여부는 세 사례 모두 별도 문제다.

#### E4-C. 정답 독립성과 실패 보존

- [ ] 별도 사례 작성자가 E2의 고정 명세를 읽고 원문에서 최소 의미 변경으로 변형을 작성한다. 주입 연산의 이름 자체를 정답으로 사용하지 않는다.
- [ ] 두 실제 검토자는 검사기 출력과 의도한 오류 유형·정답을 가린 상태에서 시퀀스를 독립 판정한다. 제시 순서를 섞고 가능한 범위에서 원문과 변형을 인접하게 제시하지 않는다. 판정 후 원문 대조로 변경의 적절성을 확인한다.
- [ ] 변경 위치, 변경 전후 문장, 의도 유형, 검토 판정, 실제 근거, 기대 최초 위반 사건을 기록한다. 의도와 사람 판정이 다른 경우도 보존한다.
- [ ] 모순이 명확하지 않은 변형은 `INVALID_MUTATION` 또는 `AMBIGUOUS_GOLD`로 구분해 전체 생성 수·유효율과 함께 보고한다. 정답 보류 사유는 최초 검사 실행 전에 고정하며, 검사기가 놓쳤다는 이유로 제외하지 않는다.
- [ ] 코드·주입 규칙·원문 목록·정답·분모를 고정하고 해시·작성자·검토자·시점을 기록한 뒤 최초 검사한다. 생성 프로그램은 제안 검사기의 반환값으로 사례를 채택·재시도하지 않는다.
- [ ] AI는 초안 작성에 쓸 수 있으나 이를 사람 검토나 정답 독립성으로 대체하지 않는다. 실제 역할 분리가 없으면 그 제한을 기록한다.
- [ ] 최초 실패와 실행 오류도 보존한다. 수정 후 동일 집합의 결과는 재시험으로 표시하고 최초 독립 평가와 분리한다.

| B2 | 동일 구조화 입력과 고정 명세를 사용하는 독립 단순 FSM/규칙 검사 | 상태 보유 경쟁 baseline; 제안 검사기의 갱신 함수를 호출하지 않음 |
| Proposed | 기존 지속 요구 검사 | 평가 대상 |

같은 경로에서는 모든 비교군에 동일한 입력·증거를 제공한다. 입력 로딩과 schema는 공유할 수 있으나 정답 및 B2 판정 로직은 제안 구현에서 복제하지 않는다. FSM과 동률이면 성능 우월성을 주장하지 않는다.

#### E4-E. 지표와 판정 규칙

- 유형별 모순 주입 탐지율, 전체 TP/FP/TN/FN, precision/recall/F1, specificity, 정상 원문·C1의 오경보율, U1의 모순 오판율, 최초 위반 위치 일치율을 보고한다.
- 먼저 gold×prediction의 전체 범주표(정상/모순/Unknown/추출실패/실행실패)를 제시한다. 이진 탐지는 gold가 정상 또는 모순인 사례에서 `명시적 모순 경보`를 positive로 정의한다. 실제 모순에서 Unknown·추출실패·실행실패는 미검출 FN이다.
- 정상 gold에서 경보하지 않은 Unknown·실패는 이진 경보 지표상 TN에 포함되므로, specificity는 **정상 사례 비경보율**이라고 설명한다. 확실한 정상 판정률과 보류·실패율을 별도로 반드시 보고하여 판단 능력으로 오해하지 않게 한다. 실행 실패가 많은 방법의 낮은 오경보율을 우수성으로 해석하지 않는다.
- gold Unknown은 이진 지표에서 별도 분리하고 정답 Unknown 유지율과 모순 오판율을 보고한다. 유효 gold가 없는 변형은 생성 유효율 표에 남긴다. 분모 0인 지표는 미산출 사유를 표기한다.
- 정상→모순 대응쌍에서 원문 정상 판정과 변형 탐지 모두 맞은 비율을 추가한다. 원문이 Unknown인 경우는 이 대응쌍 지표에 넣지 않는다.
- 95% 구간과 방법 간 차이는 원본 장면을 단위로 대응 재표집 2,000회(seed `20260930`)한다. 동일 장면의 모든 변형은 함께 뽑는다. 소규모 유형별 지표는 건수·분모를 우선 보고하며 분모 소실과 불안정한 구간을 표시한다.
- 위 지표는 **고정한 인위적 오류 구성에서의 결과**다. 특히 precision/F1은 주입 비율의 영향을 받으므로 실제 자연 자료의 빈도·운영 성능으로 일반화하지 않는다.
- P4·장면 종료·경계는 기존 계획대로 각 4개, 총 12개 처리 시험으로 따로 수행한다. 주석 오류 탐지 TP/FP와 합산하지 않는다.

**출력:** `mutation_manifest.json`, `injected_sequences.jsonl`, `mutation_reviews.csv`, `mutation_gold.jsonl`, `injection_evaluation.json`, `baseline_predictions.jsonl`, `processing_fault_results.json`.

### 11.1 대응의 중심 주장과 수용할 한계

Reviewer-1.pdf 3쪽 전체, Reviewer-2.md, Reviewer-3.md를 다시 읽고 최초 실행 및 보완 재시험과 대조하였다. R1 Major 1은 자연 오류 자료 구축이 어렵다면 제목·초록·결론의 주장을 rule execution/feasibility framework로 제한하는 대안을 명시한다. 이번 개정은 이 대안을 채택한다. 자연 발생 오류 수집을 다시 필수 선행 조건으로 삼지 않는다.

중심 주장: “연속 CoC에서 행동 의무와 해제 근거를 연결하여 시간 순서 및 조건의 모순과 근거 부족을 구분하고, UPPAAL 모델의 판정으로 문제 사건·의무·근거를 추적할 수 있는 프레임워크를 제시한다. 통제된 작성 시나리오에서 그 실행 가능성을 확인한다.”

시간적 검증은 중심 모델의 사건 순서·의무 유지·조건 충족 순서를 의미한다. 정량적 반응 제한 시간은 기존 보조 분석으로 분리한다. 영상의 사실성, 모든 위험에 대한 설명 완전성, 자연 오류 정확도, 범용 NLP 추출, 차량 안전은 주장하지 않는다. UPPAAL 사용 자체나 단순 FSM 대비 정확도 우위를 독창성으로 삼지 않는다.

작성 시나리오의 문장과 프레임은 함께 작성됐으며 사람 검토로 확정한 자연 원문 정답이 아니다. 본문의 원문→모델 사례에는 “작성 시나리오/설계자 부여 프레임”을 표시한다. 기존 자연 문장을 예시로 쓰려면 원문 ID와 실제 추출 출력(미상 포함)을 그대로 제시하고, 수작업 해석은 별도 주석으로 구분한다.

R3 7의 개발 미사용 독립 시험 요구와 R1 3/R3 9의 검토자 신뢰도 개선은 현 결과만으로 해소되지 않는다. 주장 축소는 이 요구를 수행했다는 뜻이 아니다. 답변서에서 미해결 범위를 명시하며 게재 수용을 보장하지 않는다.

### 11.5 추가 실험의 우선순위와 답변서 문장

현재 확정 범위의 실험은 수행했으므로 우선 전체 원고와 답변서를 정렬한다. 자연 오류 수집·대규모 생성·모델 학습을 다시 필수 작업으로 넣지 않는다. R3 7을 더 강하게 대응하려면 보완 모델을 고정한 뒤 개발에 쓰지 않은 구조적 조합에 별도 정답을 부여한 후속 시험이 도움이 된다. 다만 같은 작성자가 사례와 구현을 모두 만든 경우 독립 외부 검증이라고 부를 수 없으며, 이름/문장만 바꾼144개 반복은 독립성을 확보하지 않는다. 이는 선택적 보강이고 이번144/144를 새 독립 성능으로 재명명하는 대안은 허용하지 않는다.

R1-M1 답변 방향: “자연 발생 오류에 대한 일반적 탐지 성능을 입증하기에 기존 자료가 부족하다는 지적을 수용합니다. 이에 논문의 주장을 연속 CoC의 시간적·조건적 관계를 구조화하여 실행하고 문제 근거를 추적하는 프레임워크의 적용 가능성으로 제한합니다. 통제 시나리오의 최초 결과와 보완 후 동일 사례 재시험은 구분하여 제시하고, 자연 오류 정확도를 입증한 결과로 해석하지 않습니다.” 실제 원고 수정 전에는 이 문장을 완료형 답변서로 제출하지 않는다.

R3-7 답변 방향: “기대 결과에 맞는 사례만 제시하는 한계를 줄이기 위해 고정 시나리오의 최초 결과와 불일치 사례를 모두 보존하였습니다. 보완 모델의 결과는 같은 사례에 대한 개발 후 재시험임을 명시합니다. 개발 미사용 독립 시험을 수행했다는 주장은 하지 않으며, 이 한계에 맞추어 논문의 평가 범위를 제한합니다.” 이는 요구의 직접 충족이 아닌 제한 수용이라는 점을 숨기지 않는다.
