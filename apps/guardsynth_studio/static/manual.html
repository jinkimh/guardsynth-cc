1. 처음 시작·영상 선택

  1. 작업 탭에서 전달받은 검토자 ID와 Studio 비밀번호로 로그인합니다. API 키를 입력하는 화면이 아닙니다.
  2. 기존 영상 아래의 추출 READY를 눌러 시점 목록을 엽니다. 준비된 영상은 다시 업로드하거나 추출할 필요가 없습니다.
  3. 시점 번호를 고르고 현재 t0와 영상을 대조합니다. 기존 CoC 초안을 검토·수정하고 저장 상태를 확인합니다.
  4. 근거가 충분한 항목만 사람이 승인합니다. 불명확하면 보류하고 이유를 기록합니다.

2026-09-30 공개 영상 데모는 13개 시점 중 화면 7번·13번에 생성 초안이 준비되어 있습니다. 두 시점은 연결 시연용이며 자동 승인된 학습 자료가 아닙니다. 데모 호출 한도 2회는 이미 소진되어 추가 생성 없이 이 초안을 검토하면 됩니다. 다른 영상에도 같은 시점에 초안이 있다는 뜻은 아닙니다.

새 영상을 넣을 때

파일 선택은 브라우저를 사용하는 사람의 PC 파일을 고르는 기능입니다. 서버 파일 경로를 입력하는 기능이 아닙니다. 출처·라이선스·업로드 권한을 기록하고 MP4/H.264 파일을 선택합니다(1 GiB, 30분, 3840×2160 이하). 외부 모델 전송 승인은 별개입니다. probe가 READY가 된 뒤 초 간격 추출을 실행합니다. 주행 ID를 모르면 비워 두고 계보 확인을 보류하세요. 파생 영상은 먼저 부모 영상과 구간을 기록합니다.

2. 저장·승인·완료는 다릅니다

  • 저장: 수정한 초안을 보존합니다. CoC·행동과 출처·관찰 결합·적용성 입력은 자동저장됩니다. 출처 기록·관찰 결합 기록·적용성 저장 버튼으로 즉시 반영할 수도 있습니다. 고급 JSON은 구조 초안 저장 버튼이 필요합니다.
  • 승인: 해당 항목과 그 근거 버전을 사람이 확인했다는 기록입니다. 다른 항목이나 행동 레이블까지 승인하지 않습니다.
  • 보류(HOLD): 근거 부족·불확실성 때문에 결정을 미룹니다. 거절(REJECT): 현재 내용이 잘못되었거나 부적절합니다. 어느 쪽도 학습 승인으로 바뀌지 않습니다.
  • 시점 검토 완료: 검토를 마쳤다는 기록입니다. 문제가 남으면 REVIEW_COMPLETE_HELD로 완료할 수 있습니다. 검토완료 수와 학습적격 수는 별개입니다.

상단의 저장됨을 확인하세요. 저장 실패 시 초안은 브라우저 대기함에 남으며 서버 저장 완료가 아닙니다. 409는 다른 창·작업이 먼저 버전을 바꾼 경우입니다. 최신본과 내 초안을 비교한 뒤 의도한 내용만 새 버전으로 저장하세요. 새로고침 전에 실패를 해결하는 편이 안전합니다.

상위 항목을 수정하면 그 항목의 승인이 해제되고 의존하는 제약·검사·CNL 등에 STALE(재검토)가 표시됩니다. 과거 승인 이력은 남습니다. 오래된 결과를 최신 승인으로 사용하지 않습니다.

3. 최대 7개 프레임과 현재 시점

오른쪽 끝이 현재 판단 시점 t0이고 나머지는 과거입니다. 영상 시작에서는 7개보다 적습니다. 다음은 한 프레임씩 이동하여 1–7 → 2–8, 이전은 2–8 → 1–7로 돌아옵니다. 처음부터 끝까지 모든 추출 시점을 선택할 수 있습니다.

이전 썸네일을 누르면 판단 시점 자체가 바뀝니다. 현재 이미지만 크게 보려면 현재 프레임 확대를 누르고 복귀로 돌아오세요. 시간은 실제 추출 PTS에 근거하며 프레임 번호가 초를 뜻하지 않습니다.

미래 시점을 이미 보았더라도 앞선 시점의 답변에 그 지식을 섞지 마세요. 모델 입력은 t0까지로 제한되지만 사람이 기억한 미래 내용을 자동으로 판별해 주지는 않습니다.

4. CoC: 관찰에서 판단까지

영상에 보이는 내용과 추론을 구분하고 모델 원출력과 대조해 수정합니다. 원출력은 고급 패널에서 읽을 수 있으며 수정본과 별도로 보존됩니다. 아래 예시는 특정 영상의 정답이 아닙니다.

입력기록할 내용참고 예시
관찰 사실현재·과거 프레임에서 직접 확인되는 모습선택 영역 가장자리에 사람이 보인다.
관계대상과 영역 사이의 위치·상호 관계사람의 위치가 제안한 진입 영역과 겹친다.
가정판단에 필요하지만 아직 확인하지 못한 전제자차가 표시 영역으로 진입하려는 상황이라고 가정한다. 실제 경로는 확인이 필요하다.
미확인가림·정보 부족 등으로 판단할 수 없는 내용가려진 영역에 다른 사람이 있는지는 알 수 없다.
행동 근거관찰과 불확실성이 선택에 미치는 이유영역과 사람의 겹침이 해소되었는지 확인하기 전에는 진입 보류가 적절하다.
승인할 CoC 본문앞의 항목들을 대조해 사용자가 직접 정리한 최종 검토 문장현재 보이는 사람과 진입 영역이 겹친다. 가림 때문에 전체 해소 여부는 불명확하므로 추가 확인 전 진입을 보류한다.

CoC 본문은 나머지 다섯 칸에서 자동 조립되지 않습니다. 사실·가정을 고쳤다면 본문도 일치하게 고치세요. 가정 예시를 사실로 옮기거나 모르는 경로를 확정하지 마세요.

과거·현재 근거만 사용함 확인은 t0 이후의 관찰·정답을 가져오지 않았다는 사람의 확인입니다. 미래/정답 누출 발견은 실제 누출을 발견했을 때 표시합니다. 두 체크를 형식적으로 누르지 마세요. 입력은 자동저장되며 본문·인과성·누출을 검토한 뒤 CoC 승인을 따로 합니다.

5. 별도 행동 레이블

CoC 문장이나 솔버의 허용 행동을 그대로 정답으로 복사하지 마세요. 관찰 근거에 비추어 적절한지를 독립적으로 검토합니다. 물리적으로 가능한 행동 전부를 적절하다고 표시하는 것이 아닙니다. 단일 정답을 강제하지 않으며 여러 행동이 동시에 적절할 수 있습니다.

행동의미·구분
영역 진입 (ENTER_ZONE)지정한 영역으로 들어가는 행동
진입 보류 (DEFER_ENTRY)진입 결정을 미루는 행동. 급제동·정지 명령이 아님
주행 속도 유지 (MAINTAIN_SPEED)이미 움직이는 상태의 속도 유지
정지 유지 (HOLD_STOP)이미 멈춘 상태를 계속 유지

적절(APPROPRIATE)은 근거상 타당, 부적절(INAPPROPRIATE)은 근거상 부당, 판단 불가(UNKNOWN)는 정보 부족입니다. 해당 없음(NOT_APPLICABLE)은 해당 행동 상황 밖이라는 판단이며 미확인을 대신하지 않습니다. 빈 선택은 미기록입니다. 예: 자차가 정지했는지조차 모르면 정지 유지의 적절성을 단정하지 않습니다.

현재 학습 지원은 진입·진입 보류 두 행동뿐입니다. 속도 유지·정지 유지 키에 어떤 값이든 기록하면, 해당 없음이어도 현재 profile에서 미지원으로 보류됩니다. 진입 전용 작업에서 쓰지 않는 두 칸은 비워 두세요. 필요한 행동이 미지원이라면 솔직히 기록하고 보류해야 하며 통과를 위해 거짓 레이블을 만들면 안 됩니다. 이미 저장한 추가 행동 키의 제거가 필요하면 고급 action의 labels를 검토하여 수정합니다.

행동 근거와 선택은 자동저장됩니다. 별도 행동 승인 버튼을 사용하세요. 해당 없음에 불필요한 메모를 강제하지 않습니다.

6. 대상 점·진입 영역 그리기

CoC 생성에는 도형 편집이 필요 없습니다. 현재 CoC 생성 요청은 과거·현재 프레임과 연결된 차량 상태를 사용하며 대상 점·영역 표시는 모델에 보내지 않습니다. 이 단계의 목적은 후속 제약 검토에서 “어느 객체 때문에 어느 공간의 진입을 검토하는가”를 명시하는 것입니다.

대상 점은 해당 조건과 관련된 객체 하나를 가리킵니다. 모든 차량·보행자를 표시하는 작업이 아닙니다. 선행 차량도 CoC 관찰과 행동 이유에는 포함하지만, 점을 찍는 것만으로 추종·감속 제약을 지원하지는 않습니다. 현재 지원하는 보행자 충돌 조건의 대상에 선행 차량을 대신 넣지 마세요.

영역은 자차의 진입 여부를 판단할 도로 공간입니다. 차량의 테두리나 영상 전체, 자동 추정된 주행 경로가 아닙니다. 예를 들어 횡단보도 보행자 때문에 진입 보류를 검토한다면 대상은 그 보행자이고 영역은 검토하는 횡단보도 진입 공간입니다. 픽셀 표시로 실제 경로나 거리가 확인되는 것은 아닙니다.

현재 nuScenes의 선행차·공사 구간 감속 CoC 예제는 도형을 비워 두고 생성·검토할 수 있습니다. 이후 지원하는 진입/보류 제약을 검토할 때 출처·대상·영역의 연결을 확인하고 별도 승인합니다. 작업자는 물리적 보행자 충돌의 대상일 수 있으나 손짓·STOP 지시의 권한은 별도 통제 규칙입니다. 차량 제동등은 정지 표지판이 아닙니다.

대상의 정의: 현재 검토하는 진입 조건의 근거로 지정할, 현재 프레임의 특정 객체 하나입니다. CoC가 설명하는 모든 객체나 화면에서 가장 큰 객체를 뜻하지 않습니다. 먼저 검토할 조건을 정한 다음, 그 조건과 관계있는 객체를 지정하세요.

검토 상황대상 선택·이름 예주의할 구분
횡단보도 보행자와 충돌할 수 있어 진입 보류를 검토해당 보행자의 몸체 안을 클릭. 이름: ‘횡단보도 오른쪽 끝 파란 옷 보행자’주변의 무관한 보행자 전부를 표시하지 않습니다. 선택 자체가 충돌 조건 확인이나 승인은 아닙니다.
주도로에 진입할 때 양보 의무를 검토현재 기본 템플릿은 개별 차량 대신 진입 문맥을 사용하므로 대상 점을 억지로 지정하지 않습니다.주도로 관계·규칙 근거를 확인해야 합니다. ‘개별 대상 없는 문맥 의무 확인’은 객체를 찾지 못했다는 표시가 아닙니다.
선행차와 공사 구간 때문에 감속을 검토하는 nuScenes 예제선행차를 CoC 관찰·이유에 기술합니다. 이 예제의 CoC 생성에는 대상 점이 필요 없습니다.추종·감속 계약은 현재 지원하지 않습니다. 선행차를 보행자 대상에 대신 연결하지 않습니다.

대상 이름은 위치 + 객체 종류 + 구별 특징으로 적습니다. ‘위험 요소’, ‘차량’만으로는 다른 검토자가 같은 객체를 찾기 어렵습니다. 현재 프레임에서 객체를 식별하지 못하거나 검토할 조건이 불명확하면 선택하지 않고 미해결로 남기세요.

  1. 도형 편집에서 대상 점을 선택하고 위 기준에 맞는 객체의 보이는 몸체 안을 한 번 클릭합니다. 점은 객체 식별용이며 충돌점·중심점·접지점의 실측을 뜻하지 않습니다. 다시 클릭하면 점의 위치가 바뀝니다.
  2. 영역 꼭짓점을 선택하고 자차가 진입할 것으로 검토하는 구역의 서로 다른 꼭짓점을 3개 이상 순서대로 클릭합니다. 선이 교차하지 않게 하세요. 장애물 외곽을 따라 그리는 기능이 아닙니다.
  3. 영역·대상 이름을 구체적으로 적고 도형 반영 및 저장됨을 확인합니다. 클릭도 자동저장 대기함에 들어갑니다.
  4. 잘못 그렸다면 대상 점 완전 삭제·영역 완전 삭제로 현재 도형을 지우고 다시 기록합니다. 과거 승인 이력까지 삭제하는 기능은 아닙니다.

현재는 시점당 대상 하나·영역 하나입니다. 여러 영역 편집기가 아닙니다. 좌표는 0–1의 정규화 픽셀일 뿐 실제 거리·차량 궤적이 아닙니다. 의도 경로와 영역을 근거로 특정할 수 없으면 결합을 미해결로 남기세요. 완료를 위해 경로를 만들어내지 마세요.

7. 규칙 출처

출처 ID는 같은 규칙을 연결하는 식별자입니다. 문서 버전·조항 위치·정확한 원문을 함께 기록하고, 원문을 직접 확인했을 때 출처 내용 확인을 선택합니다. 원문 해시는 저장 시 자동 계산되며 직접 조작할 필요가 없습니다.

  • POLICY: 명시적으로 정한 연구 정책. 법규 인증이 아닙니다.
  • EXTERNAL: 외부 권위 근거. 단순 출처 칸 외에 고급 source JSON에서 jurisdiction(관할), applicable_scope(적용 범위), effective_period(효력 기간)를 실제 근거로 채워야 승인할 수 있습니다.
  • UNVERIFIED_MODEL: 미검증 모델 제안. 현재 출처 승인 대상으로 사용할 수 없습니다.
정책 기록 예시 — 승인된 규칙이 아님

ID: example_entry_policy, 버전: 검토 중인 정책판, 위치: 진입 조건 항목, 인용 예: “검토 영역의 보행자 충돌이 해소되지 않으면 진입을 보류한다.” 이는 형식 설명용 문장입니다. 사용자가 실제 채택·검토한 원문으로 바꿔야 하며 주도로 양보 규칙까지 자동으로 뒷받침하지 않습니다.

국가·법규·대기시간을 영상만으로 추정하지 마세요. 입력은 자동저장되고 출처 기록으로 즉시 반영할 수 있습니다. 출처 승인은 별도입니다. 고급에서 외부 권위 추가 필드를 편집했다면 단순 출처 폼의 재기록은 그 추가 필드를 보존하지 않으므로 고급 JSON으로 수정·확인하세요.

8. 관찰 판단과 대상·영역 결합

보행자 관련 위험(ped)은 선택한 진입 영역과 보행자의 충돌 관련 조건이고, 주도로 양보 필요(road)는 그 진입 맥락의 양보 조건입니다. 현재 프레임·선택 영역·근거 범위를 명시해 판단합니다.

판단예시·의미
참 TRUE관련 보행자가 선택 진입 영역과 충돌하는 근거가 확인됨
거짓 FALSE충분히 보이는 선택 영역에서 해당 충돌 조건이 해소되었음을 확인함. 화면 밖까지 전역 부재라고 주장하지 않음
미확인 UNKNOWN가려진 영역 때문에 해소 여부를 확인할 수 없음
근거 충돌 CONFLICT같은 조건·같은 시점에 대한 유효한 근거들이 양립하지 않음. 서로 다른 시점이나 ped와 road가 다른 판단이라는 뜻이 아님

근거 유효는 이 조건에 관련되고 현재 시점에 유효한 관찰이라는 뜻입니다. CoC 문장만으로 보이지 않는 신호가 있다는 독립 근거를 만들 수 없습니다. UNKNOWN·CONFLICT·무효 근거는 해제나 안전 확인으로 취급되지 않습니다.

개별 대상 없는 문맥 의무 확인은 특정 객체가 없는 문맥 의무라는 점을 확인한 경우입니다. “대상이 안 보이니 필요 없다”는 체크가 아닙니다. 예를 들어 주도로 양보 문맥의 역할은 별도 검토가 필요합니다.

대상·영역·프레임 근거 결합 확인은 그 대응을 검토했다는 표시입니다. 승인에는 현재 causal 프레임의 영역과 근거가 필요합니다. 입력은 자동저장되며 관찰 결합 기록 후 별도 승인합니다.

9. 제약 제안과 계약

실제 모델 제약 제안에는 승인된 CoC·출처·관찰 결합이 필요합니다. 실제 VLM 요청 버튼은 호출 예산을 사용합니다. 수동 초안 버튼은 모델 호출이 없지만 사람이 내용 전체를 검토해야 합니다.

수동 진입 제약 템플릿은 ped와 road 두 조건을 제안합니다. 임의로 입력한 인용문에서 두 규칙을 자동 도출한 것이 아닙니다. 출처가 각각을 실제로 뒷받침하는지 고급 proposal에서 확인하고 불필요하거나 잘못된 후보는 수정하세요. 대상·영역·조건·출처 참조·적용성·해제 의미를 검토한 후 제안을 승인합니다.

승인 제안의 계약 초안 작성 후 고급 contract의 의무·대상·영역·출처 연결을 대조하고 계약도 별도로 승인합니다. 현재 profile은 두 술어와 진입/보류이며 horizon=3은 추상 판단 단계입니다. 3초나 프레임 3개가 아닙니다. 시간 임계·가속 등은 지원하지 않으며 임의로 진입 보류로 근사해 통과시키지 않습니다.

10. EBLC Q1–Q5 · CNL · 결합

승인 계약·출처·관찰 결합으로 검사합니다. 화면의 검사 요약을 확인하세요. 저장된 검사 결과에는 질의별 기대/실제값이 남습니다. SAT는 주어진 가정 아래 가능한 경우가 있다는 뜻이고 UNSAT는 그런 경우가 없다는 뜻입니다. 금지 행동 질의는 UNSAT가 기대 성공일 수 있습니다.

  • Q1: 현재 전제가 충족 가능한지 확인(SAT). 전제 모순으로 모든 금지가 공허하게 통과하는 것을 막습니다.
  • Q2: 현재 진입 가능성, 보류 가능성, 관찰 전제의 반대가 불가능한지 확인합니다.
  • Q3: 검토 필요 여부와 미관찰 이전 활성 상태의 양쪽 가능성을 확인합니다.
  • Q4: 가상 다음 단계에서 전체 조건 해소가 가능한지, 해소 후 진입·보류가 가능한지, 미해소 진입이 금지되는지 확인합니다.
  • Q5: 별도 가상 시나리오의 활성→해제→재활성, 미확인·충돌·무효 시 유지, 일부 의무만 해제한 경우의 진입 금지를 확인합니다.

전체 PASS는 필수 질의가 비어 있지 않고 기대값과 일치해야 합니다. solver UNKNOWN·timeout·오류는 통과가 아닙니다. 관찰 UNKNOWN의 보류 정책 검사는 PASS일 수 있어도 학습 적격은 보류됩니다. 가상 미래 witness를 영상 관찰로 가져오지 마세요. SAT나 PASS는 장면 사실·법규·실차 안전을 인증하지 않습니다.

같은 버전의 검사 후 CNL을 생성합니다. 문장이 유창한지만 보지 말고 주체·대상·영역·조건·해제·허용 행동이 계약과 일치하는지 확인하고 CNL을 승인하세요. 검사/CNL은 파생 읽기 전용 값입니다. 의미가 틀렸다면 출처·관찰·계약을 고치고 다시 검사·생성합니다.

결합은 승인 CoC·CNL·별도로 승인한 행동이 필요합니다. 원 CoC 뒤 제약 블록이 붙고 원본은 보존됩니다. 결합 본문과 행동의 충돌을 확인한 뒤 결합도 승인합니다. 전체 흐름이 항상 학습 적격으로 끝난다는 보장은 없습니다.

11. 적용성·검토 완료

UNREVIEWED는 미검토, APPLICABLE은 적용됨, NOT_APPLICABLE은 후보와 근거를 검토한 결과 적용 제약 없음, UNRESOLVED는 적용 여부 미해결입니다. 판단 근거와 규칙 후보 검토 여부를 기록·저장하고 별도로 승인하세요.

빈 제안·생성 오류·거절·미지원은 미적용의 증거가 아닙니다. 예를 들어 규칙 후보를 아직 검토하지 않았다면 UNRESOLVED로 남겨야 합니다. 현재 위험이 FALSE인 것은 규칙의 해제 조건일 수 있어 규칙 자체의 미적용과 다릅니다. 명시 승인한 미적용은 나머지 조건 충족 시 baseline만 가능하며 강화 자료로 세지 않습니다.

12. 학습 분할과 내보내기

같은 원본·주행 및 겹치는 파생 클립은 한 그룹으로 묶어 train(학습), validation(검증), test(평가) 중 하나에만 배정합니다. 인접 프레임이나 baseline/강화본을 서로 다른 분할에 넣지 마세요. 계보가 불명확하면 확인하지 말고 분리 보류로 둡니다. 그룹 split은 확정 버튼으로 저장합니다.

출력 모드입력과 목표
COC_TARGET입력은 causal 프레임·질문. 목표는 승인 CoC 또는 강화 결합 CoC와 별도 행동 레이블/미확인 mask.
ACTION_WITH_CONTEXT입력에 사람이 정답 누출 없음을 검토·승인한 context를 추가. 강화본에는 CNL도 추가. 목표는 별도 행동 레이블/미확인 mask.

context에는 정답 행동·미래 지식을 숨겨 넣지 않습니다. 고급 context의 text와 no_label_leakage를 검토하고 별도 승인해야 합니다. 의미 분리가 어렵다면 COC_TARGET 또는 초안으로 보관하세요. provenance의 전체 기록을 모델 입력에 펼치지 마세요.

DRAFT는 보류 초안도 내보내지만 학습 적격이 아닙니다. DEVELOPMENT_TRAINING은 보류 항목을 제외하고 이유를 기록합니다. 현재 추출 전체의 저장된 버전 snapshot을 고정하며 실행 중 수정과 섞지 않습니다. READY와 포함/제외 수를 확인하고 다운로드하세요. 완료 수와 적격 수는 다르며 승인 레이블이 독립 평가 정답이라는 뜻도 아닙니다.

13. 고급 JSON · 원본 · 수동 파생문

단순 폼에 없는 출처 효력 범위, 제약/계약 세부 수정, context·수동 파생문을 기록할 때 사용합니다. 항목 선택 → 기존 내용을 읽고 허용 필드 수정 → 구조 초안 저장 → 필요한 항목 재승인 순서입니다. 항목을 바꾸기 전에 수정 내용을 저장하세요. JSON은 큰따옴표·쉼표·괄호 형식을 지켜야 합니다.

원출력·hash·origin·승인·검사 상태를 고쳐 적격을 강제하지 마세요. CNL 수동 문장은 derived에 별도로 기록하며 renderer 원문과 검사 보증을 덮어쓰지 않습니다. 예: 표현을 바꾼 문장은 수동 파생문으로 보관하되 결정적 CNL 학습 export에는 사용하지 않습니다. 고급 패널을 열면 제약 노출 이력이 기록됩니다.

14. 선택 구간 검토

현재 추출의 화면 번호로 시작·끝을 지정합니다(최대 100시점). 구간 CoC 생성은 시점별 개별 모델 요청으로 비용과 예산을 소비합니다. 한 번의 공짜 묶음 요청이 아닙니다. 현재 데모에서는 실행하지 마세요.

일괄 승인은 항목을 고르고 차이·시점 미리보기에서 각 내용과 이전 승인을 읽은 뒤 확인 체크를 하고 표시한 버전 일괄 승인을 누릅니다. 예: 7–8번이면 두 시점 모두 검토해야 합니다. 하나라도 버전이 바뀌면 전체가 거부되므로 새 미리보기로 다시 검토하세요.

15. 원본 계보·권한·로그아웃

파생 클립 업로드 전에 부모 video ID와 원본 구간을 마이크로초(μs)로 입력합니다. 예: 2초~5초는 2000000~5000000입니다. 부모 ID는 영상의 원본 계보 식별자에서 확인합니다. 알 수 없는 관계를 임의로 만들지 마세요.

동일 원본/주행의 그룹을 병합할 때는 그룹 ID를 쉼표로 나열하고 근거를 기록합니다. 상충 split은 다시 검토해야 하고 기존 export가 무효화될 수 있습니다. 사용권한 철회는 관련 export 다운로드와 후속 사용을 차단하며 과거 파일을 물리적으로 삭제하는 버튼은 아닙니다.

로그아웃은 대기 수정을 먼저 저장하고 세션과 로컬 대기함을 정리합니다. 저장 충돌이 있으면 먼저 해결하세요. 브라우저 초안 캐시에 민감 텍스트가 남을 수 있습니다. 비밀번호나 API 키를 답변·JSON에 기록하지 마세요.

16. 작업 상태·오류 읽기

  • QUEUED 대기, RUNNING 실행 중, SUCCEEDED 결과 생성 성공입니다. 성공이 사람 승인을 뜻하지는 않습니다.
  • STALE_RESULT는 실행 도중 입력이 바뀌어 결과를 적용하지 않은 상태입니다. 최신 초안을 확인하세요.
  • FAILED 실패, TIMED_OUT 시간 초과, CANCELLED 취소입니다. 취소는 결과 적용을 막지만 이미 전송한 비용 취소를 보장하지 않습니다.
  • 재시작 후 INTERRUPTED 또는 모델 결과 불명의 OUTCOME_UNKNOWN은 자동 유료 재시도하지 않습니다. 명시 재시도도 호출 한도를 소비합니다.
  • PROVIDER_BUDGET은 호출 상한 소진입니다. 반복 클릭하거나 한도를 임의 변경하지 마세요. DISABLED/503은 설정·승인 조건 미충족입니다.
  • FUTURE는 t0 이후 근거가 섞인 요청입니다. 근거 시점을 바로잡으세요. 409는 버전 충돌이며 비교 후 다시 저장해야 합니다.
  • auth/429/refusal/incomplete/JSON/schema 오류는 생성 실패로 남습니다. 모델·계정을 자동 전환하거나 실패를 승인하지 않습니다.
